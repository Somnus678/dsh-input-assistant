## 已执行的浏览器与桌面证据

Edge 夹具使用生产输入助手界面和控制器、真实 Lexical 编辑器，确认：优化回填后原生一次撤销恢复原文；改动查看和显式还原正常；暂存先保存再清空、仅经用户操作恢复；测量灰字后 Tab 插入正确。它使用测试模型输出，没有付费模型调用，记录中 `realDshDesktop:false`。

桌面探针运行在真正的 DeepSeek Harness 可执行进程中，核对加载服务确属已安装的 `dsh-input-assistant@0.1.0`。通过认证 Gateway 调用 `settings/get`、`status`、`drafts/list`、`drafts/save`、`drafts/delete` 和 `drafts/clear`，完成草稿持久化往返、单条删除、按会话隔离及清空。报告 `generatedRequests:0`，没有写入会话事件；探针结束后清除了测试草稿并拆除探针连接。该证据验证了真实宿主接线，尚不能替代生产编辑器的完整原生交互验收。

原生桌面操作使用可见的官方生产界面，没有向编辑器注入脚本：输入一条含中文和 emoji 的合成草稿，暂存后清空，一次 Ctrl+Z 精确恢复；显式追加暂存文字后，一次 Ctrl+Z 撤回追加；通过真实按钮调用辅助模型并回填，打开 diff，再还原原文。一次 Ctrl+Z 撤销还原，下一次 Ctrl+Z 撤销优化。验证完成后恢复起初的空草稿，并通过精确内容匹配清除测试暂存，保留用户其他数据。这些覆盖了已列出的操作；中文字符输入不等于已验证中文 IME 候选组合。

小样本使用 `deepseek-account / deepseek-flash`，6 次均记录为最低推理档 `off`、temperature 0、256 输出 token 上限。公开基线只是提示词研究适配，没有运行其完整插件。fishcg 的提取适配有一处语气提示偏差，报告保留了该限制；样例接近部分参考提示词示例，另有明显样本偏差。不能把这些结果解释为同类领先，完整 60 条结果与人工语义评分继续保持 `not_evaluated`。[完整小样本说明](smoke-comparison.md)

### 关于恢复脚本的更正

开发过程中曾把"恢复脚本在 `originallyMissing` 链接处失败"记为 `0.1.1` 的阻断性缺陷。复核确认该现象由**开发会话沙箱对工作区盘符的文件系统重定向**引起（junction 被写成 `\??\Global\…`，同一进程无法跟随），不属于归档或脚本缺陷：在普通用户路径（C 盘临时目录、随包 Node 24.19.0）上，`0.1.1` 原始归档的完整流程可正常完成，105 条测试全部通过。`0.1.2` 对恢复脚本的改动因此是**健壮性改进**（幂等、`--repair`、缺目标跳过、链接识别、创建兜底），不是对既有缺陷的修复。
