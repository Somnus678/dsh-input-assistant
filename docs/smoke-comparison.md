# 低用量真实模型试验

日期：2026 年 10 月 22 日。此试验用于检查真实模型接线和观察少量输出，不是完整质量验收。

## 方法和用量

在当前官方 DSH Windows `0.2.1-rc.2` 宿主中，通过已有 `ctx.llm` 连接串行执行 6 次辅助请求。路线为 `deepseek-account / deepseek-flash`，目录显示 DeepSeek-V4.1-Flash；界面模型标记为 1017。六次均显式选择模型声明的最低推理档 `off`、temperature 0、输出上限 256 tokens，不自动重试，不创建 Agent，不写主会话事件。

三个操作各选一个合成案例，并与一个公开实现的提示词比较。候选使用实际已安装插件的提示词构造和输出校验。基线原提示词仅保存在不随发行分发的研究目录，通过同一模型请求；没有安装或执行基线插件，因此没有比较其完整 UI、调度或后处理。

此次模型试验发生在新增设置页及三级优化强度之前；候选核心 SHA-256 为 `02667fa4afc0342806e1aca3ecb33607276a430c8c523f26695c597ce08c3dd0`。最终版本的新强度策略只做了结构与保护回归，未逐档追加真实模型测量；本表不能作为三级强度效果的验收结果。

提供商记录的六次用量合计：输入 **2,706 tokens**（其中缓存读取 256）、输出 **101 tokens**，总计 **2,807 tokens**。另有一次通过实际桌面按钮发起的短草稿优化，已成功回填，但未单独采集其 token 用量；因此不能把 2,807 表述为本次所有操作的精确总用量。其余自动化、宿主和 UI 夹具均不调用付费模型。

## 观察

| 操作 | 合成场景 | 候选观察 | 基线观察 | 单次耗时，候选 / 基线 |
|---|---|---|---|---|
| 优化 | 简短、已经清晰的解释要求，禁止改文件或加功能，保护一个路径 | 保持原稿；路径占位映射完整恢复 | PI 调整措辞，保留约束和路径 | 626 / 1,075 ms |
| 下一句 | 用户要求解释两个概念，助手只解释了一个 | 建议继续询问尚未解释的概念 | studyzy 同样建议继续解释该概念 | 772 / 786 ms |
| 续写 | 已有前缀请求解释缓存失效 | 返回可直接追加的短后缀 | fishcg 返回可直接追加的较短后缀 | 578 / 862 ms |

原始安全报告保留在开发工作区的临时证据目录（`.test-runtime/benchmark/`，已被 `.gitignore` 排除，不随仓库或安装包分发），其中含提示词版本、输出、结束原因、用量和耗时。研究材料不随安装包分发。

## 能说明什么

这三个案例中的候选输出符合基本操作要求，实际模型调用链能够工作。优化案例原稿已经清晰，保持原文也符合本插件策略；不能把“改写更多”直接算作优化更好。

**当前不能证明模型效果处于同类领先地位。** 每种操作只有一个案例，未覆盖歧义弃权、纠偏、长历史和多语言；下一句案例还与提示词示例相近，存在明显有利偏差。单次延迟也受缓存、网络和顺序影响。没有进行匿名多人语义评分，没有调用 Claude/Codex 的内部预测链路，也没有完成 60 条固定评测。

工程上可以核实的优势是功能整合、版本校验、保护片段、原生撤销和暂存恢复；这些提高可控性，不能代替意图符合率的证据。完整质量状态继续保持 `not_evaluated`，详见 [评测流程](evaluation.md) 和 [验收记录](validation.md)。
